# Scénario local jetable Pointage → Paie (UX-15)

Ce scénario est réservé au développement local. Il crée le salarié, son embauche, la période et les journées via les API métier. Il utilise exclusivement le conteneur `galaxam-ux15-pg`, la base `galaxam_ux15`, l'utilisateur PostgreSQL `ux15_app` et le port loopback `55434`. Les scripts refusent une autre identité de conteneur/base/API.

## Démarrage

Vérifier d'abord que `55434`, `18082` et `18090` sont libres. Ne pas arrêter la stack locale existante.

```sh
docker run -d --name galaxam-ux15-pg --restart=no \
  -e POSTGRES_DB=galaxam_ux15 \
  -e POSTGRES_USER=ux15_app \
  -e POSTGRES_PASSWORD=ux15_ephemeral_only \
  -p 127.0.0.1:55434:5432 postgres:15-alpine

until docker exec galaxam-ux15-pg pg_isready -U ux15_app -d galaxam_ux15; do sleep 1; done

cat backend/conception/bdd/01_schema_core_securite.sql \
    backend/conception/bdd/02_schema_referentiels_rh.sql \
    backend/conception/bdd/03_schema_employes_contrats.sql \
    backend/conception/bdd/04_schema_conges.sql \
    backend/conception/bdd/05_schema_pointage.sql \
    backend/conception/bdd/06_schema_paie.sql \
  | docker exec -i galaxam-ux15-pg psql -X -v ON_ERROR_STOP=1 -U ux15_app -d galaxam_ux15
```

Les schémas canoniques contiennent deux dossiers salariés d'exemple. Avant de démarrer Spring Boot, les effacer de **cette base jetable seulement**. Cette remise à zéro enlève leurs dépendances par cascade; elle ne crée aucune donnée de scénario. Le compte d'administration synthétique sera réensemencé au démarrage du backend.

```sh
scripts/recette/ux15-reset-canonical-demo-data.sh
```

Démarrer Spring Boot dans un terminal. Le secret admin est temporaire et réservé au conteneur UX-15.

```sh
cd backend
SPRING_PROFILES_ACTIVE=local \
SPRING_DATASOURCE_URL=jdbc:postgresql://127.0.0.1:55434/galaxam_ux15 \
DATABASE_USERNAME=ux15_app DATABASE_PASSWORD=ux15_ephemeral_only \
CORS_ORIGIN=http://127.0.0.1:18090 \
BOOTSTRAP_ADMIN_ENABLED=true \
GALAXAM_DEFAULT_ADMIN_NAME='UX15 Admin Recette' \
GALAXAM_DEFAULT_ADMIN_EMAIL=ux15.admin@example.invalid \
GALAXAM_DEFAULT_ADMIN_PASSWORD='UX15-Temp-Pass-2026!' \
JWT_SECRET='ux15-temporary-jwt-secret-for-isolated-development-recipe-2026' \
UPLOAD_DIR=/tmp/galaxam-ux15-uploads \
mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=18082
```

Démarrer Vite dans un autre terminal :

```sh
cd frontend
VITE_API_BASE_URL=http://127.0.0.1:18082/api/ npm run dev -- --host 127.0.0.1 --port 18090
```

## Scénario métier

Dans un troisième terminal, fournir le mot de passe temporaire au script. Le script vérifie l'identité/port/montages du conteneur, interroge la base attendue, exige qu'elle soit vide de salariés et vérifie un salarié canari après création pour confirmer que Spring écrit dans ce conteneur.

```sh
UX15_ADMIN_PASSWORD='UX15-Temp-Pass-2026!' scripts/recette/ux15-scenario.py
```

Le scénario choisit le mois entièrement échu précédent, crée et valide une embauche par API, ouvre une période par `OPEN`, saisit les plages horaires reçues de l'API du site TMM, puis exige un préflight limité à un seul salarié avant `SUBMIT` et `APPROVE`. `horaireContinu` n'est pas activé par le script. Il vérifie ensuite par PostgreSQL la présence des journées et du snapshot gelé. Il s'arrête avant le calcul de paie.

Ouvrir l'URL `payrollVariablesUrl` imprimée par le script dans React, puis examiner les étapes disponibles de la campagne. Le compte `ROLE_ADMIN` est un compte de recette synthétique; cette recette ne prouve pas l'accès d'un DAF à privilèges limités.

## Nettoyage

Arrêter uniquement les processus Spring Boot et Vite UX-15 avec `Ctrl-C`, puis supprimer le conteneur nommé de la recette et son volume Docker anonyme associé avec `-v`. Cette option ne supprime pas de volume nommé ; la commande cible uniquement `galaxam-ux15-pg` :

```sh
docker rm -f -v galaxam-ux15-pg
python3 -c 'import shutil; shutil.rmtree("/tmp/galaxam-ux15-uploads", ignore_errors=True)'
```

Ne pas exécuter `docker compose down` sur le projet local.
